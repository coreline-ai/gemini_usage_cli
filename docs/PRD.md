## 1. 제품 개요

### 1.1 제품 비전

Gemini Usage CLI는 Google Gemini API 사용량을 실시간으로 추적하고 시각화하는 터미널 기반 도구입니다. AI 에이전트(Antigravity)와 통합하여 자동 로깅을 설정하고, 개발자가 API 사용 패턴을 모니터링할 수 있도록 지원합니다.

### 1.2 문제 정의

| 문제 | 설명 |
|------|------|
| 사용량 파악 어려움 | Gemini API 사용량을 실시간으로 확인할 방법이 없음 |
| 비용 관리 | 토큰 소비량을 추적하지 않으면 예상치 못한 비용 발생 가능 |
| 수동 기록 | 매번 수동으로 사용량을 기록하는 것은 비효율적 |
| 시각화 부재 | 터미널에서 사용량을 직관적으로 확인할 방법 부재 |

### 1.3 솔루션

- **자동 로깅**: AI 에이전트가 자동으로 사용량을 JSONL 파일에 기록
- **실시간 대시보드**: 터미널에서 토큰 사용량과 요청 횟수를 시각화
- **반응형 업데이트**: 파일 변경 감지 시 자동으로 대시보드 갱신
- **간편한 설정**: 대화형 설정 마법사로 쉽게 구성

## 2. 대상 사용자

### 2.1 주요 사용자

| 사용자 유형 | 설명 | 니즈 |
|------------|------|------|
| AI 개발자 | Gemini API를 사용하는 개발자 | 토큰 사용량 추적, 비용 관리 |
| DevOps 엔지니어 | AI 시스템 운영 담당자 | 실시간 모니터링, 알림 |
| 프로젝트 매니저 | AI 프로젝트 관리자 | 사용량 리포트, 예산 계획 |

### 2.2 사용자 스토리

1. **개발자로서** 현재 프로젝트의 Gemini API 사용량을 확인하고 싶다
2. **개발자로서** 실시간으로 토큰 소비를 모니터링하고 싶다
3. **개발자로서** AI 에이전트가 자동으로 사용량을 기록하도록 설정하고 싶다
4. **DevOps로서** 터미널에서 빠르게 사용량 현황을 파악하고 싶다

## 3. 기능 요구사항

### 3.1 핵심 기능 (MVP)

#### F1: 사용량 스캔 (`scan`)
- **우선순위**: P0 (필수)
- **설명**: `~/.gemini/usage.jsonl` 파일을 파싱하여 사용량 통계 표시
- **출력 정보**:
  - 총 토큰 수 (입력 + 출력)
  - 총 요청 횟수
  - 마지막 활동 시간
  - 현재 상태

#### F2: 실시간 모니터링 (`scan --watch`)
- **우선순위**: P0 (필수)
- **설명**: 파일 변경 감지 시 대시보드 자동 갱신
- **기능**:
  - `fs.watch()` 기반 파일 감시
  - 대화형 명령어 지원 (`/refresh`, `/help`)
  - Ctrl+C 두 번으로 안전 종료

#### F3: 대화형 설정 (`setup`)
- **우선순위**: P0 (필수)
- **설명**: Antigravity 자동 로깅 규칙 설정
- **옵션**:
  - 프로젝트 레벨: `.antigravity/rules.md`
  - 전역 레벨: `~/.antigravity/rules.md`

#### F4: 인증 (`auth`)
- **우선순위**: P2 (향후)
- **설명**: API 서버 인증을 위한 토큰 관리
- **현재 상태**: 예시 구현만 완료

### 3.2 UI/UX 요구사항

| 항목 | 요구사항 |
|------|----------|
| 색상 테마 | Google 브랜드 색상 (Blue, Red, Green, Yellow) |
| 로고 | ASCII 아트 "GEMINI" 텍스트 |
| 박스 | 유니코드 박스 문자로 데이터 테두리 |
| 숫자 포맷 | K(천), M(백만) 단위 자동 변환 |
| 이모지 | 각 항목별 직관적인 이모지 표시 |

### 3.3 데이터 요구사항

#### 로그 파일 형식
- **경로**: `~/.gemini/usage.jsonl`
- **형식**: JSONL (JSON Lines)
- **스키마**:
```json
{
  "timestamp": "ISO 8601 형식",
  "project": "프로젝트 이름",
  "model": "모델 이름 (예: gemini-2.0-flash)",
  "usage": {
    "input_tokens": "입력 토큰 수",
    "output_tokens": "출력 토큰 수"
  }
}
```

## 5. 기술 아키텍처

### 5.1 기술 스택

```
┌─────────────────────────────────────────────┐
│                  CLI Layer                   │
│            (Commander.js + Inquirer)         │
├─────────────────────────────────────────────┤
│                  UI Layer                    │
│           (Chalk + String-width)             │
├─────────────────────────────────────────────┤
│                 Core Logic                   │
│        (Log Parser + File Watcher)           │
├─────────────────────────────────────────────┤
│               Configuration                  │
│                  (Conf)                      │
├─────────────────────────────────────────────┤
│                File System                   │
│          (~/.gemini/usage.jsonl)             │
└─────────────────────────────────────────────┘
```

### 5.2 모듈 구조

| 모듈 | 역할 | 의존성 |
|------|------|--------|
| `index.ts` | CLI 진입점, 명령어 정의 | commander, inquirer |
| `ui.ts` | 터미널 UI 컴포넌트 | chalk, string-width |
| `log-parser.ts` | 로그 파일 파싱 | fs, path |
| `setup-helper.ts` | 설정 파일 생성 | fs, path |
| `config.ts` | 설정 관리 | conf |
| `logger.ts` | 사용량 로깅 | fs, path |

## 8. 제약사항 및 가정

### 8.1 제약사항

1. **로컬 전용**: 현재 버전은 로컬 파일 시스템만 지원
2. **단일 사용자**: 다중 사용자 환경 미지원
3. **JSONL 형식**: 다른 로그 형식 미지원
4. **영어 CLI**: 명령어 출력은 영어로 고정

### 8.2 가정

1. 사용자는 Node.js 18 이상이 설치되어 있음
2. 터미널이 ANSI 색상을 지원함
3. Antigravity 에이전트가 로깅 규칙을 준수함
4. 로그 파일 크기가 합리적인 수준으로 유지됨
